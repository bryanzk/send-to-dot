# 故障排除

按“入口 → OAuth → 事件 → 读取 → 附件显示”定位，先记录失败阶段，避免连续换码、换地址或重复发送。日志只提供版本、状态和脱敏阶段；不要贴 owner/phone/read token、授权码、完整 OAuth URL、私人图片或数据库。

## 入口打不开、DNS 错误、502

检查自己的主机、进程、DNS、证书和反向代理；核对实际 HTTPS origin。Mac/笔记本需保持在线。代理应转发到 `127.0.0.1:43187` 并设置正确 Host，不能只转发 MCP 而漏掉网页、API、OAuth 或发现路径。

临时隧道停止后旧名字可能消失。不要手改已有 OAuth URL、复用旧 state/code，或修改系统 DNS/VPN 来掩盖部署故障。稳定日用使用自己的固定 HTTPS；新 origin 要正常迁移、隔离原数据库绑定并重新连接。

## preflight 失败、启动后没有监听

确认 Node 支持 `node:sqlite`，Python/Pillow 版本正确，`DOT_INBOX_PYTHON` 在启动服务的同一环境可见。服务管理器通常不会继承交互终端的环境。检查端口占用和初始化输出，但不要输出秘密文件内容。

新安装使用 `scripts/setup.mjs`。旧版低层配置若仍是 `initializePhone: true`，首次 launch 会初始化后退出；不要重复运行它来续期既有授权，也不要覆盖已存在的秘密。存储密钥必须与原数据库匹配。

## Connect 按钮一直转

先确认服务发现接口可达，再确认是否留有本次失败的 OAuth 错误标签/窗口。只关闭本次旧错误页，正常重开自己的插件页；不要刷新旧错误 POST，不清除全站数据，也不要修改无关插件或不停点击 Connect。

当前项目曾在真实浏览器中恢复这一状态：关闭旧错误页、重开已有插件后，按钮可用并正常打开 owner 表单。该方法不能证明所有平台转圈都有相同原因。仍卡住时记录平台阶段和后台是否收到新授权请求；不要靠反复提交耗尽限流。

## `Origin rejected`

使用最新代码，正常从自己的插件重新发起授权，核对实际页面 origin。旧版授权 HTML 的 `Referrer-Policy: no-referrer` 会使浏览器表单携带 `Origin: null`；已修正为仅授权页使用 `same-origin`。不要以允许 null、去掉来源检查、放开 CORS 或复制完整授权 URL 作为修复。

手机上传也要求正确 origin 和 bearer；原生 Shortcuts 客户端须显式设置约定的 Origin。Origin 本身不是认证凭据。

## 授权后没有回到 ChatGPT／出现 `Try later`

旧版 `form-action 'self'` 可能拦截授权后的既定外站回跳；最新代码只允许配置中经过校验的精确 HTTPS 回跳，并保留 owner、PKCE 和来源检查。确认使用最新包且服务器实际加载了代码。

`Try later` 对应限流时停止提交，按 `Retry-After` 等待并先解决原因。已有授权码不等于换 token 成功，读取授权也不等于事件/附件验收成功。不要加大权限、创建全权限密钥或禁用 CSP 来绕过。

## 工具能调用，但事件不能订阅

重新检查[平台资格](PLATFORM_REQUIREMENTS.md)、工作区控制、插件事件发现及服务器协议。普通 MCP 工具可用不证明支持 MCP Events。确认目标是本人既有 dot，插件发现 `file.created`，且服务器实际收到、验证并保存了 `events/subscribe`。

订阅最多一小时，父授权一天。检查到期、平台续订和撤销状态。一次 callback 2xx 不能替代事件确实抵达目标对话。

## 已收件，但没有回应

先看上传 receipt、file_id、到期时间和队列状态。上传成功、回调已接受、原图被读取、助手回复各自是独立阶段。

401 需要正常重新配对/授权；404 可能已过期或无访问权。一次最大8MiB、1600万像素，仅单帧 PNG/JPEG；类型、配额或幂等冲突按错误提示处理。源图一小时后过期，不从其他私人目录“找回”来绕过授权。

网络超时结果未知时先查看原dot；简化Android页会保留未确认状态，不提供自动或手动重试入口。不要改问题或换图盲重传。底层同提交ID和同内容去重用于受控恢复。服务端 eventId 稳定不代表接收端可以省略去重。

## 助手看懂了图，但聊天没有原图附件

这是不同能力：`get_image` 的 MCP 图片结果不保证变成原生聊天附件。需要当前代理使用自己的私有 Space/Library 保存工具，再以助手身份通过支持的原生附件工具发送。服务器没有通用公开的 ChatGPT 消息注入 API，也不持有平台账号凭据。

检查现有事件任务是否配置附件桥接、是否有该工具能力、是否拿到 native Library ID 与真实发送回执。创建/发送结果不确定时暂停核实，不能重建文件或反复发消息。accepted 不等于用户已看见。不要伪装用户上传消息。

## Android 分享菜单没有 Send to dot

先确认是在 Android personal profile 的 Chrome 安装的应用，而不只是打开普通网页。核对固定 HTTPS origin、manifest 与 service worker、系统分享目标及单张 PNG/JPEG 限制。网页选图成功不能证明系统分享通过；应在实际手机上测试相册与截图来源。

本项目已有单用户系统分享试用证据，尚未覆盖所有手机/Chrome 版本。不要要求安装第二份 ChatGPT，也不要把 iOS Safari 当成相同接收器。

## 删除、断开和保留时间

断开手机会清本地配对和暂存，不等于服务端撤销，也不删除已到达的服务器副本。收件箱按一小时时限清理；原图可能含元数据。

Space/Library 中的附件是独立持久文件，不随源图 TTL、授权撤销或聊天删除自动消失。通过相应产品的正常删除流程处理；事件重放不得默默重建用户已经删除的附件。

## 提交问题前

用非私密生成样本复现，提供系统/浏览器/Node/Python版本、失败阶段、脱敏 HTTP 状态、是否重启或改过域名，以及哪些环节实际通过。不要附当前部署的配置、密钥、SQLite、真实授权链接或个人图片。不要仅写“全部测试通过”而省略真机和平台边界。
